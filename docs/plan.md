**Google first-login bounce fixed + the auth gatekeeper switched on (2026-08-31, live on production):** Nic's report — the first Google sign-in bounced to `/login?error=auth`, the second attempt worked, logout/login fine after. Root cause, reproduced locally and on production with a crafted stale cookie: a **stale session cookie** (an old login whose refresh key is dead) survived untouched to the OAuth callback; the callback's Supabase client tried to refresh it in the background while the PKCE code exchange ran; the failed refresh's clean-up (`_removeSession`) deleted the one-time **code-verifier** cookie mid-flight → `AuthPKCECodeVerifierMissingError` → `?error=auth` — and that same response finally cleared the stale cookie, so the retry worked. Underneath it: **`middleware.ts` at the repo root had never run on any deployment** — with the app under `src/`, Next.js only reads `src/middleware.ts` (build manifest empty; unknown pages 404'd instead of bouncing to login). Pages and routes guard themselves, so nobody noticed — but the middleware is the only place a server-side token refresh can be *saved* (Server Components can't write cookies), so refreshed sessions were lost and browsers were left holding dead cookies, which is how the stale cookie arose. Fixes (dev → preview → main same day): the callback drops any session cookie before creating its client and **logs the exact failure reason** (it used to swallow it — `[auth/callback]` in Vercel logs); the middleware moved to **`src/middleware.ts`**, skips `/api/*` (every route self-guards; crons, Telegram webhooks and the signed digest link carry their own secrets), `/ext/*`, `/auth/*` and `/mockups/*`, and copies Supabase's cookie updates onto every redirect (the documented `NextResponse.redirect` pitfall); the login page now shows the `?error=auth` / `account_removed` message (the red line existed but was never fed). Two new standalone suites (`src/lib/auth/session-cookies.test.ts` 9 checks, `middleware-scope.test.ts` 20 checks); all 11 suites green. Verified with curl probes on local, the dev preview (through the new bypass secret) and production: gatekeeper alive, stale cookie cleared on the first redirect, API/cron/webhook/ext/mockup paths untouched. **Vercel Protection Bypass for Automation** set up by Nic (dashboard only — the admin-page button was offered and declined); secret in `.env.local`, never in code.
